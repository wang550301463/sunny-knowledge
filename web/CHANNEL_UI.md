# 企业微信渠道与双向绑定 UI

本阶段连接 Go channel 的真实 REST 合同。页面不生成机器人、群、身份绑定或回答的演示数据，也不把 202 检测接受或 pending 群操作显示为完成。

## 入口与操作

- `/settings/channels`、设置中的“消息渠道”：平台管理员查看最多 100 个渠道，创建/编辑、真实检测、启停、群授权与消息诊断。管理身份不代表空间内容读取权。
- 已共享发布 Agent 卡片的“企微渠道”链接预选 Agent。先读取当前发布指针，再读取对应固定配置，空间选择限于其范围与当前可读空间；列表支持后续游标加载。服务端保存时再次校验并冻结 Agent 配置。
- 新配置保存为停用；修改已启用配置明确提示并执行“保存并停用”。BotID 不可修改，替换密钥留空保留。成功检测版本与当前版本一致且状态可用，才显示可执行启用；实际连接状态持续从服务器读取。
- 群 ChatID 从受控企微事件手动登记，不支持自动发现。群受众 ID 首次生成后不可更换。启用必须重新确认“面向本群当前及后续成员”，请求 scope 不超出渠道 scope。
- Group 使用 `desired_enabled` 编辑、`sync_state` 判断结果。`pending` 始终展示禁用及请求范围。PUT 和 reconcile 使用当前审阅的 `base_version`；失败也刷新 GET，保留服务器的持久待同步状态，不乐观启用或自动换新版本重发。
- `/channels/bindings` 是任何已登录用户自己的实际绑定列表；解除操作只使用当前用户 Bearer 指向选中的外部账号。成功后重新读取 active/version，不宣称局部状态就是服务器结果。

## 一次性凭据与登录流程

企微私聊 `/绑定` 的链接为 `/channels/bind#challenge=…&token=…`。

已登录页面严格校验两个 fragment 参数，立即替换掉地址栏 fragment，将 proof 仅保留在组件内存。用户明确认领当前账号后，只展示服务端返回且形状与 challenge 匹配的 `/确认` 命令，并标为“等待企微私聊确认”。只有同一企微用户发送该命令并收到机器人确认，才完成绑定。页面没有伪造的“已发送即成功”按钮，也不依据另一个绑定变化推断此次挑战完成。

首次登录仍使用现有安全 Auth 流程；不将 proof 搬入 query、OIDC state、sessionStorage 或 localStorage。登录后页面明确指引用户返回企微重新打开同一未过期链接，或重新发送 `/绑定`。此两步体验是当前实现的已知边界，后续可采用受保护的服务端 continuation 优化。

认领错误、隐藏命令和卸载均清除页面持有的凭据，迟到响应不能重新显示。敏感命令使用固定行数，避免 AntD autoSize 把值复制到页面外的全局隐藏测量 textarea。未获得挑战状态/精确过期时间 API，因此不制造倒计时；界面明确从企微生成起 5 分钟有效，以服务器校验为准。

BotSecret 输入不进入浏览器持久存储；每次提交时清空表单，响应 decoder 只选定公开 Config 字段，丢弃意外返回的明文/密文字段。修改、检测、启用失败会展示真实错误与当前状态，结果不确定时不自动重发。

## 验证与边界

2026-09-08 渠道专项 3 个文件、15 个行为测试通过：凭据字段丢弃、严格 fragment、pending 禁用、发布版本范围与配置 CAS、密钥清空、群重新披露/desired_enabled、202 与实际检测区分、精确启用 CAS、失败对账后读取、StrictMode、迟到回包、隐藏命令 DOM 清理、过期/拒绝及自助解绑。

这是 Vitest/jsdom 的真实 HTTP 合同模拟验证，不替代真实企微 Bot、浏览器 OAuth 或跨服务联调。真实测试机器人凭据仍由部署本地提供。Agent 渠道完整结果的只读运行/引用专属授权合同由平台后续集成；诊断页运行链接需要当前授权，不能绕过群受众限制。首版不含附件、主动通知或自动群发现。
