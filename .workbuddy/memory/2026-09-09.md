## 执行：以 Codex 为准回填（用户确认）

### 三种写入机制（关键经验）

Codex 写文件用了三种方式，恢复时必须都解析：

1. `cat > <path> <<'EOF' … EOF` → rollout `payload.input`，**1 级转义**（`\n` = 换行）
2. `{"<path>":{"type":"add","content":"…"}}` 载荷 → 直接 `json.loads` 两次即可，**内容最干净**（14 个会话含此模式，227 个文件 / 883 KB）
3. `*** Begin Patch / *** Update File: <path> / @@ / +行` → **2 级转义**（`\\n` = 换行，`\\"` = 引号）

**最大的坑**：unescape 顺序。必须先处理 `\\`（双反斜杠）再处理 `\n`，否则会把 Go/Python 源码里的 `\n` 字符串转义误转成真换行，导致「unknown escape / newline in string」。
修复手段：`s.replace('\\\\\n', '\\n')`（行尾反斜杠+换行 → `\n` 转义），这条对 Go 一定安全。
