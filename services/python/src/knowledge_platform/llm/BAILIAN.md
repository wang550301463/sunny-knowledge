# Alibaba Bailian deployment configuration

Official API documentation reviewed on 2026-09-08. [bailian-models.json](examples/bailian-models.json) contains three credential-free ModelConfig examples. They are explicit operator selections, not service defaults. Each object can be submitted separately to `POST /api/v1/models` through the authenticated gateway, with the credential supplied privately in the request. No real Alibaba call or model acceptance has been performed by these protocol tests.

## Endpoint and model choices

The supplied Beijing base `https://dashscope.aliyuncs.com/compatible-mode/v1` remains supported. Its native counterpart is `https://dashscope.aliyuncs.com/api/v1`. Alibaba recommends workspace domains for production; switching requires an explicit configuration version. Use a Beijing pay-as-you-go API key matching the workspace and billing plan. Token/Coding Plan keys are for interactive tools, not backend services. [Official Base URL reference](https://help.aliyun.com/zh/model-studio/base-url).

- Chat: `provider=openai`, `provider_model=qwen3.7-plus-2026-05-26`. This dated snapshot documents text output, Function Calling and structured output. The example selects it for Agent/Graphiti workflows. [Qwen3.7 Plus model reference](https://help.aliyun.com/zh/model-studio/qwen3-7-plus).
- Embedding: `provider=openai`, `provider_model=text-embedding-v4`, `dimensions=1024`, `request_dimensions=true`, `max_batch_size=10`. This Qwen3 embedding model supports the compatibility endpoint, configurable dimensions and at most 10 inputs, each at most 8192 tokens. These settings provide a concrete initial retrieval/ingest configuration. [Embedding API reference](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api).
- Rerank: `provider=dashscope_rerank`, `provider_model=qwen3.7-text-rerank`, native base ending `/api/v1`. The model documents 500 candidates and 30,000 tokens per item; the platform example deliberately limits batches to 64. [Rerank API reference](https://help.aliyun.com/zh/model-studio/text-rerank-api).

Chat and embedding append `/chat/completions` and `/embeddings` respectively. Chat config `chat_enable_thinking=false` sends HTTP `enable_thinking` at the top level. This keeps the initial Qwen probes in nonthinking mode. Null/omission sends no option; other providers retain their existing behavior. `chat_token_parameter=max_completion_tokens` selects the documented Qwen parameter. No arbitrary `extra_body`, search option or reasoning history is forwarded. [Chat compatibility reference](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions).

The native rerank adapter appends `/services/rerank/text-rerank/text-rerank`, sends `{model,input:{query,documents},parameters:{top_n}}`, and reads `output.results`, top-level `usage` and `request_id`. It does not send `return_documents`, which is not documented for Qwen3.7 text rerank. Only normalized indices and scores are returned.

An alternative `qwen3-rerank` configuration must explicitly use `provider=dashscope_rerank_compatible` and base `https://YOUR_WORKSPACE.cn-beijing.maas.aliyuncs.com/compatible-api/v1`. This adapter appends `/reranks` (plural), sends flat `{model,query,documents,top_n}`, and reads top-level `results`, `usage` and `id`. The two rerank protocols never fall back to each other or to Cohere `/rerank`. Both validate exact result count, unique indices and finite scores in [0,1]; scores only compare candidates within one request. [Official protocol distinctions](https://help.aliyun.com/zh/model-studio/text-rerank-api).

## Limits and acceptance

Example character caps are local resource controls, not token counts. Provider limits still apply; callers must split ingest batches and bound retrieval candidates. No provider input is silently truncated. Concurrency and queue caps are per model per replica; multiple workers multiply capacity. Fixed model names and configuration UUIDs preserve application selections, but only the chat example uses a documented dated snapshot. The cited embedding/rerank references provide no dated snapshot for these selected names; an immutable application configuration cannot freeze vendor weights behind a model name.

When the private key is available, create the three configurations, save returned immutable UUIDs in the downstream service selections, and run each `/api/v1/models/{id}/test`. For chat, request `test_tools=true,test_stream=true`; verify each returned capability, not HTTP status alone. Then exercise representative chat/tool/structured output, a two-item embedding batch with exactly 1024 finite values per vector, and rerank with a known candidate list. Record configuration UUIDs, capability outcomes, safe provider request IDs and usage. Avoid recording prompts, raw model outputs or keys in the acceptance log. Failed probes remain failed and require an explicit configuration correction, never a synthetic fallback.
